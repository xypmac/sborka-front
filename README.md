# sborka

Фронтенд приложения для управления заказами на сборку мебели. Next.js + Redux Toolkit.

---

## Стек

- Next.js (App Router)
- Redux Toolkit
- React Hook Form + Yup
- react-datepicker, date-fns
- SCSS Modules

---

## Установка и запуск

```bash
npm install
npm run dev   # localhost:3000
```

Требует запущенный бэкенд (`F:\git\sborka-api`, localhost:4000).

---

## Роли пользователей

| Роль | Доступные страницы |
|---|---|
| Администратор | Все. Удаление заказов, деактивация пользователей |
| Бригадир | Все, кроме удаления/деактивации |
| Салон | `/`, `/orders/*`, `/orders/create` — только свои заказы |
| Сборщик | `/`, `/orders/[id]` — только заказы где он исполнитель (WORKER) |
| Замерщик | `/`, `/orders/[id]` — только заказы где он замерщик (MEASURER) |

---

## Структура

```
src/app/
  store/          — Redux: session, orders, users, calendar
  containers/     — умные компоненты (страницы, формы)
  components/     — UI-компоненты
```

## Календарь рабочих дней

Личный производственный календарь доступен Сборщику и Замерщику.

**Где находится:**
- `/profile` — Сборщик/Замерщик видит вкладку "Календарь рабочих дней" в своём профиле, устанавливает статусы самостоятельно
- `/calendar` → клик по имени пользователя → модалка → вкладка "Календарь рабочих дней" — Администратор управляет статусами чужих пользователей

**Статусы дней:** `10` = Свободный, `11` = Выходной

**API (личный календарь):**
- `POST /calendar/getForCurrent` — получить свой календарь за месяц
- `POST /calendar/setDayForCurrent` — установить статус дня себе
- `POST /calendar/getById` — получить календарь пользователя (admin)
- `POST /calendar/setDayUser` — установить статус дня пользователю (admin)

**Влияние на `/calendar` (список пользователей):**
- Статус "Выходной" из личного календаря имеет приоритет над "В работе" из заказов
- Статус "В работе" (`12`) вычисляется из заказов: `DATE_WORK === date && WORKER/MEASURER === ID`
